# 每日麻醉文献精读：开源配置指南

仓库：<https://github.com/sxq0218-afk/Anesthesia-Literature-Daily>

本指南用于帮助下载或 Fork 项目后的使用者完成自己的 AI、PubMed、Buttondown 和 GitHub Actions 配置。每位使用者必须使用自己的账户和密钥；仓库不提供共享生产密钥。

## 一、最小本地配置

### 1. 安装环境

- 安装 Git。
- 安装 Node.js 22.13 或更高版本，推荐 22.17.1。
- 准备一个兼容 OpenAI Chat Completions 格式的 AI API。
- 准备真实联系邮箱，用于 NCBI 和 Crossref 礼貌访问。

### 2. 下载项目

```bash
git clone https://github.com/sxq0218-afk/Anesthesia-Literature-Daily.git
cd Anesthesia-Literature-Daily
npm ci --ignore-scripts
cp .env.example .env.local
```

### 3. 修改 `.env.local`

DeepSeek 示例：

```dotenv
LITERATURE_MODE=production
DEPLOY_ENV=local
SITE_URL=http://localhost:3000

AI_PROVIDER=deepseek
AI_BASE_URL=https://api.deepseek.com
AI_MODEL=deepseek-chat
AI_API_KEY=填写你自己的密钥
AI_TEMPERATURE=0.1
AI_MAX_TOKENS=7000
AI_TIMEOUT=90000
AI_RETRY_COUNT=1

NCBI_EMAIL=填写你的真实联系邮箱
NCBI_API_KEY=
NCBI_TOOL=anesthesia_literature_daily
CROSSREF_MAILTO=填写你的真实联系邮箱
```

注意：

- `.env.local` 不能提交到 GitHub。
- `NCBI_API_KEY` 可不填；不填时程序使用较低请求频率。
- 更换模型时同时修改 `AI_PROVIDER`、`AI_BASE_URL` 和 `AI_MODEL`。
- 不要在命令行参数、Issue、截图或日志中展示密钥。

### 4. 验证

无 AI、无邮件的真实元数据预检：

```bash
npm run literature:fetch
```

完整本地生成：

```bash
npm run literature:daily
npm run publication:prepare
npm run dev
```

## 二、GitHub Actions 自动运行

### 1. Fork 仓库

点击仓库右上角 `Fork`，在自己的账户下创建副本。后续的 Secrets、Variables、Buttondown 和 AI 费用都属于你自己的账户。

### 2. 配置 Secrets

进入：

`Settings → Secrets and variables → Actions → Secrets`

新增：

- `AI_API_KEY`：必需。
- `BUTTONDOWN_API_KEY`：需要邮件推送时必需。
- `NCBI_API_KEY`：可选。

### 3. 配置 Variables

进入：

`Settings → Secrets and variables → Actions → Variables`

基础变量：

```text
EMAIL_DELIVERY_ENABLED=false
AI_PROVIDER=deepseek
AI_BASE_URL=https://api.deepseek.com
AI_MODEL=deepseek-chat
AI_TEMPERATURE=0.1
AI_TIMEOUT=90000
AI_RETRY_COUNT=1
NCBI_EMAIL=你的真实联系邮箱
DAILY_ARTICLE_COUNT=5
DAILY_MAX_CANDIDATES=2000
DAILY_CANDIDATE_PAGE_SIZE=200
DAILY_JOURNAL_AUDIT_LIMIT=300
PUBMED_FETCH_BATCH_SIZE=150
DAILY_AI_CALL_LIMIT=50
DAILY_TOKEN_LIMIT=500000
DAILY_MAX_INPUT_CHARS=60000
```

邮件变量：

```text
NEXT_PUBLIC_BUTTONDOWN_USERNAME=你的Buttondown用户名
BUTTONDOWN_SUBSCRIBER_LIMIT=100
```

网站变量可选：

```text
SITE_URL=https://你的长期稳定域名
```

没有稳定域名时可暂不配置 `SITE_URL`，不要填写带短期令牌的预览链接。

### 4. 第一次运行

1. 暂时保持 `EMAIL_DELIVERY_ENABLED=false`。
2. 打开 `Actions → 每日文献邮件`。
3. 点击 `Run workflow`，选择 `main`。
4. 检查配置、测试、生成、构建和安全扫描日志。
5. 确认 AI 与 Buttondown 均为自己的账户。
6. 将 `EMAIL_DELIVERY_ENABLED` 改为 `true`。
7. 再手动运行一次完成邮件验收。

默认计划任务为每天 UTC 23:00，即北京时间约 07:00。GitHub 可能延迟数分钟。

## 三、Buttondown 配置

1. 注册或登录 Buttondown。
2. 创建 newsletter。
3. 在设置中确认 newsletter 用户名。
4. 创建 API Key。
5. 将 API Key 存入 GitHub Secret `BUTTONDOWN_API_KEY`。
6. 将用户名存入 Variable `NEXT_PUBLIC_BUTTONDOWN_USERNAME`。
7. 在 Buttondown 中添加测试订阅者并完成二次确认。
8. 手动运行工作流，确认收到完整邮件。

程序会按当日期次主题查询已有邮件；处于排队、计划或已发送状态时不会创建第二封。

## 四、修改选文规则

- `config/topics.json`：检索主题。
- `config/journals.json`：期刊名单。
- `config/journal-metrics.json`：影响因子、年份和来源。
- `config/scoring.json`：评分门槛、候选上限、临床与基础配额。

默认规则：

- 影响因子严格大于 5。
- 近 30 天不足时扩展到 180 天，再扩展到 360 天。
- 每日最多 5 篇，目标为 4 篇临床证据和 1 篇基础研究。
- 系统评价、Meta 分析、指南和共识计入临床证据。
- 360 天仍不足时少发，不降标准、不跨类别补位。

影响因子属于会更新的数据。修改时应同时记录指标年份和可核验来源，不要凭印象填写。

## 五、上线前检查清单

```bash
npm run test:literature
npm run test:email
npm run test:deployment
npm run lint
npm run security:scan
npm run build:edgeone
npm audit --omit=dev --omit=optional
```

必须确认：

- 测试全部通过。
- 安全扫描 findings 为 0。
- 仓库中不存在 `.env.local`、真实 Key、邮箱授权码或订阅者名单。
- GitHub Actions 只在 `main` 分支发送。
- 正式内容先保存成功，再调用邮件服务。
- Buttondown 使用的是自己的测试 newsletter。

## 六、常见问题

### 为什么没有满 5 篇？

这是质量保护的正常结果。360 天内不能满足影响因子、相关性、评分、去重和 4+1 构成时，系统会少发。

### 为什么工作流没有执行？

检查：

- Actions 是否启用。
- `EMAIL_DELIVERY_ENABLED` 是否为 `true`。
- 必需的 Secrets 和 Variables 是否齐全。
- 仓库默认分支是否为 `main`。

### 可以直接用于临床决策吗？

不可以。本项目是医学教育和科研辅助工具。AI 解读必须结合原文、指南、机构规范和专业判断。
