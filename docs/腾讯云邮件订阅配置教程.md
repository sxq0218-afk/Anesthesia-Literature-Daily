# 腾讯云邮件订阅配置教程（零基础版）

本项目采用“专用收件邮箱 + 腾讯云邮件推送 SES”的方式，不需要传统服务器：用户向专用邮箱发送“订阅每日麻醉文献精读”，系统发送确认邮件；用户再次确认后，每日任务才会发送正式简报。

## 一、准备一个发信域名

1. 在腾讯云购买或使用一个您拥有管理权的域名。只用于邮件推送的域名不需要建设网站，但必须能修改DNS解析。
2. 进入腾讯云控制台，搜索“邮件推送 SES”，确认计费方式后开通。
3. 打开“发信域名”，新增一个邮件子域名，例如 `mail.example.com`。
4. 按控制台给出的记录逐条添加DNS解析，等待状态变为“验证通过”。不要开通独立IP或其他收费增值服务。
5. 在“发信地址”中创建地址，例如 `briefing@mail.example.com`。

## 二、提交两份邮件模板审核

项目已经准备好两份文件：

- `email-templates/tencent-ses-daily.html`：每日5篇精读正文。
- `email-templates/tencent-ses-notice.html`：确认订阅、订阅成功和退订通知。

在腾讯云 SES 控制台打开“发信模板”，分别新建HTML模板并上传上述文件。模板通过审核后，记下两个模板ID。不要修改 `{{变量名}}`。

## 三、准备专用收件邮箱

可以单独申请一个QQ邮箱，只用于接收订阅指令：

1. 在QQ邮箱设置中开启IMAP服务。
2. 生成“授权码”。授权码不是QQ密码。
3. 记录邮箱地址和授权码，不要发给测试用户，也不要写进代码。
4. 腾讯云发信地址的 Reply-To 建议填写这个专用邮箱，让用户可以直接回复退订。

## 四、创建腾讯云最小权限密钥

1. 在腾讯云“访问管理 CAM”中新建一个仅供本项目使用的子用户。
2. 只授予邮件推送所需权限，不要使用主账号永久密钥。
3. 创建API密钥，得到 SecretId 和 SecretKey。
4. 密钥只填入GitHub Secrets，不要粘贴到网页、代码、Issue或聊天截图。

## 五、填写GitHub Secrets

进入仓库 → **Settings** → **Secrets and variables** → **Actions** → **New repository secret**，逐个添加：

| Secret名称 | 填写内容 |
| --- | --- |
| `TENCENT_SECRET_ID` | 腾讯云子用户SecretId |
| `TENCENT_SECRET_KEY` | 腾讯云子用户SecretKey |
| `SUBSCRIBER_ENCRYPTION_KEY` | 至少32位随机字符串，设置后不要更换或丢失 |
| `SUBSCRIPTION_INBOX_USER` | 专用收件邮箱地址 |
| `SUBSCRIPTION_INBOX_PASSWORD` | 邮箱IMAP授权码 |

已有的 `AI_API_KEY`、`NCBI_API_KEY` 保持不变。

## 六、填写GitHub Variables

在同一页面切换到 **Variables**，添加：

| Variable名称 | 示例值 |
| --- | --- |
| `EMAIL_DELIVERY_ENABLED` | 首次测试前填 `false`，全部验证后改为 `true` |
| `NEXT_PUBLIC_SUBSCRIPTION_EMAIL` | 专用收件邮箱地址 |
| `SUBSCRIPTION_INBOX_IMAP_HOST` | `imap.qq.com` |
| `SUBSCRIPTION_INBOX_IMAP_PORT` | `993` |
| `TENCENT_SES_REGION` | `ap-guangzhou` |
| `TENCENT_SES_FROM_EMAIL` | `每日麻醉文献精读 <briefing@mail.example.com>` |
| `TENCENT_SES_REPLY_TO` | 专用收件邮箱地址 |
| `TENCENT_SES_DAILY_TEMPLATE_ID` | 每日简报模板ID |
| `TENCENT_SES_NOTICE_TEMPLATE_ID` | 通知模板ID |
| `EMAIL_DAILY_SEND_LIMIT` | `120` |
| `EMAIL_SEND_DELAY_MS` | `150` |
| `EMAIL_MONTHLY_COST_LIMIT_CNY` | `20` |

EdgeOne Makers也需要在项目的“环境变量”中添加公开变量 `NEXT_PUBLIC_SUBSCRIPTION_EMAIL`，值为专用订阅邮箱。它不是密码，可以公开；不要把IMAP授权码、腾讯云密钥或加密密钥填入EdgeOne。

## 七、第一次测试

1. 先把 `EMAIL_DELIVERY_ENABLED` 保持为 `false`，确认原有每日任务仍能成功。
2. 模板审核通过、发信域名验证通过后，把它改为 `true`。
3. 用您自己的测试邮箱向专用收件邮箱发送主题“订阅每日麻醉文献精读”。
4. 在GitHub仓库打开 **Actions** → **每日文献自动更新** → **Run workflow**。
5. 收到确认邮件后点击按钮或按提示发送确认邮件，再手动运行一次任务。
6. 下一期生成后应收到完整简报。Actions摘要只显示发送数量和估算费用，不显示邮箱地址。

## 八、暂停和费用保护

- 暂停邮件：把 `EMAIL_DELIVERY_ENABLED` 改为 `false`，网页和RSS仍正常。
- 每日最多发送量由 `EMAIL_DAILY_SEND_LIMIT` 控制，默认120封。
- 每月费用上限由本地或Actions环境变量 `EMAIL_MONTHLY_COST_LIMIT_CNY` 控制，默认20元；达到预测上限会停止发送。
- 不要购买独立IP。小范围测试无需该收费功能。
- 用户退订：向专用邮箱发送主题“退订每日麻醉文献精读”。

## 九、重要限制

项目使用静态加密文件保存订阅名单，不使用数据库。正常重复运行不会重复发送同一期；但如果任务恰好在发送过程中被强制终止，极少数收件人可能在人工补运行时重复收到一次。管理员应先查看Actions摘要，再决定是否补运行。
