# 每日麻醉文献精读：零基础免费部署教程

本教程面向完全不懂编程的管理员。目标是使用 GitHub Actions 每天生成内容，再由腾讯云中国站 EdgeOne Makers 免费版自动发布。网站部署本身不购买服务器、数据库、存储或统计服务；邮件订阅当前推荐使用无需域名的Buttondown，详见 [Buttondown邮件订阅配置教程](./Buttondown邮件订阅配置教程.md)。腾讯云SES配置保留为备用。

> 重要：任何页面出现“立即购买”“按量计费”“自动续费”“增值套件”“绑定付费套餐”时都不要继续。截图保存当前页面，返回免费版或停止操作。

## A. 准备 GitHub 仓库

### 1. 登录 GitHub

打开 `https://github.com`，点击右上角 **Sign in**，输入账号。正常情况下会看到个人首页；若要求验证码，按页面完成验证。

### 2. 创建或确认仓库

点击右上角 **+ → New repository**。名称填写 `Anesthesia-Literature-Daily`。小范围测试建议先选择 **Private**；若 EdgeOne 当前账户无法读取私有仓库，再考虑 Public。不要勾选自动创建 README，因为项目已有文件。点击 **Create repository**。

如果已经有同名仓库，直接进入它，不要重复创建。

### 3. 上传当前项目

当前项目第一次连接 GitHub 时，需要在项目目录初始化 Git、提交并推送。若不熟悉终端，可以在 GitHub Desktop 中选择 **Add an Existing Repository from your Local Drive**，目录选择本项目文件夹，再选择刚创建的仓库并发布。

正常结果：仓库首页能看到 `app`、`src`、`config`、`data`、`.github`、`package.json` 和 README。看不到 `.env.local`、`data/private`、`data/ai` 或真实 API Key 才是正确状态。

### 4. 确认默认分支

仓库首页左上角分支下拉应显示 `main`。若显示其他名称，进入 **Settings → Branches** 查看默认分支，并在 EdgeOne 配置相同分支。

## B. 配置 GitHub Secrets 和 Variables

### 5. 打开 Actions 配置

进入仓库，点击 **Settings → Secrets and variables → Actions**。这里有 **Secrets** 和 **Variables** 两个页签。

- Secrets：敏感值，只能重新覆盖，不能回看完整内容；
- Variables：非敏感配置，可随时修改。

### 6. 添加 AI_API_KEY

在 **Secrets → New repository secret**：

- Name 填 `AI_API_KEY`；
- Secret 粘贴当前AI服务商的真实Key；
- 点击 **Add secret**。

正常结果：列表只显示名称，不显示完整Key。若Key曾出现在公开仓库或聊天截图中，应先在服务商控制台废弃旧Key并重新生成。

### 7. 可选添加 NCBI_API_KEY

如果已申请 NCBI Key，同样新增 Secret `NCBI_API_KEY`。没有可不填，PubMed仍能低频运行。

### 8. 添加 AI 服务商变量

切换到 **Variables → New repository variable**，逐项新增：

| 名称 | DeepSeek示例 | 说明 |
|---|---|---|
| `AI_PROVIDER` | `deepseek` | 服务商代号 |
| `AI_BASE_URL` | `https://api.deepseek.com` | API基础地址 |
| `AI_MODEL` | `deepseek-chat` | 当前唯一模型 |
| `AI_TEMPERATURE` | `0.1` | 低随机性 |
| `AI_MAX_TOKENS` | `5000` | 单次最大输出 |
| `AI_TIMEOUT` | `90000` | 90秒超时，单位毫秒 |
| `AI_RETRY_COUNT` | `1` | 最多重试一次 |

更换Qwen、OpenAI、Claude等模型时，只改这些非敏感变量和相应 Secret；系统仍只调用一个当前模型。

### 9. 添加 PubMed 和网站变量

继续添加：

| 名称 | 推荐值 |
|---|---|
| `NCBI_EMAIL` | 管理员真实联系邮箱 |
| `DAILY_ARTICLE_COUNT` | `5` |
| `DAILY_CANDIDATE_LIMIT` | `120` |
| `DAILY_AI_CALL_LIMIT` | `30` |
| `DAILY_TOKEN_LIMIT` | `500000` |
| `DAILY_MAX_INPUT_CHARS` | `60000` |
| `SITE_URL` | EdgeOne正式HTTPS网址，首次部署后补填 |
| `SITE_BASE_PATH` | 留空 |

首次还没有 EdgeOne 网址时，可以先完成 EdgeOne 第一次构建；拿到网址后必须回来填写 `SITE_URL`，然后手动重新运行任务，使RSS使用正式绝对链接。

## C. 配置 GitHub Actions

### 10. 查看每日任务

进入仓库 **Actions**，左侧选择“每日文献自动更新”。工作流文件是 `.github/workflows/daily-literature.yml`。

### 11. 手动运行

点击 **Run workflow → main → Run workflow**。正常会依次显示：读取仓库、安装依赖、检查配置、核心测试、生成简报、更新RSS、静态构建、安全扫描和提交结果。

若 `SITE_URL` 尚未填写，Production检查会明确失败；这是安全行为，不会用Demo冒充成功。

### 12. 查看日志与成功标志

点击某次运行。绿色对勾表示成功。页面下方的 Summary 应显示日期、候选数、入选数、模型和Token，不显示API Key。

常见错误：

- `Missing AI_API_KEY`：回到Secrets添加或覆盖Key；
- 模型不存在/权限不足：修改 `AI_MODEL` 或服务商账户权限；
- 余额不足：到AI服务商查看余额，不要开通其他云付费服务；
- 质量检查失败：该期不会发布，上一期保留；
- 超过调用/Token上限：检查异常后再调整限制，不建议直接大幅提高。

### 13. 定时规则

当前为每天 UTC 00:37，即北京时间约08:37。GitHub定时任务可能延迟，不能承诺精确到分钟，但目标是在10点前完成。

修改时间：打开 `.github/workflows/daily-literature.yml`，编辑 `cron`。例如北京时间09:07对应UTC 01:07，即 `7 1 * * *`。不要设置每分钟运行。

### 14. 暂停与恢复

暂停：Actions → 每日文献自动更新 → 右上角 `...` → **Disable workflow**。

恢复：进入同一工作流，点击 **Enable workflow**。恢复后可手动运行一次补发；同一天已成功发布时程序会直接退出，不重复调用AI。

### 15. GitHub费用保护

本项目使用 `ubuntu-latest` 标准运行器，不使用大型收费运行器，不上传构建产物，单次最长25分钟。私有仓库每月约30次，按上限最多750分钟；实际通常更少。请在 GitHub个人 **Settings → Billing and plans → Budgets and alerts** 将Actions预算/付费支出上限设为0，并关闭自动增加付费额度。公共仓库也必须先确认历史中没有密钥。

## D. 开通 EdgeOne Makers 免费版

### 16. 登录腾讯云中国站

打开 `https://cloud.tencent.com`，点击右上角登录。免费版通常要求中国站主账号完成个人或企业实名认证；协作者/子账号可能无法领取。

### 17. 进入 EdgeOne Makers

在腾讯云控制台顶部搜索 **EdgeOne Makers**（旧名称可能显示 EdgeOne Pages），进入开发平台/Pages项目页面。

### 18. 只选择免费版

确认页面写明 **Free / 免费版 / 0元**。不要选择个人版、基础版、企业版、按量付费或增值套件。不要订阅智能加速、QUIC、图片/音视频处理、离线日志、实时日志长期存储或收费告警。

若免费版需要活动领取，只在明确显示“0元、长期有效、基础用量无超额付费”的入口领取。若页面要求支付或自动续费，停止并不要提交订单。

### 19. 创建项目并连接GitHub

在 Makers 控制台点击 **Create Project / 新建项目 → Import Git repository / 导入Git仓库**，授权GitHub，只授予当前仓库所需权限。选择 `Anesthesia-Literature-Daily` 和分支 `main`。

### 20. 填写构建配置

按下面填写：

- Root Directory：`/` 或留空；
- Install Command：`npm ci --ignore-scripts`；
- Build Command：`npm run build:edgeone`；
- Output Directory：`out`；
- Node.js：`22.17.1`；
- Production Branch：`main`。

不要添加AI_API_KEY到EdgeOne。公开网站构建不调用AI。

### 21. 第一次部署

点击 **Deploy / 部署**。正常会看到安装、构建、发布依次成功。

截至2026年7月16日，腾讯云中国站控制台实际提供的 `*.edgeone.cool` 默认地址是带校验令牌的 **3小时限时预览地址**，不是长期公开网址。不要把这个预览地址或其中的 `eo_token`、`eo_time` 写进代码、GitHub Variables、RSS或公开文档。

若页面提示添加自定义域名，而您没有已经持有且符合接入要求的域名，请停止在“预览验收”阶段。本项目禁止为此购买域名、开通按量付费或收费增值服务。中国站长期公开访问需要自有域名时，应将“长期公开网址”标记为等待管理员提供域名，而不能把3小时预览冒充正式上线。

若构建失败，检查Node版本、命令和输出目录；上一版成功部署会继续保留。

### 22. 回填SITE_URL

只有取得长期稳定、无需预览令牌的HTTPS网址后，才能回到GitHub Variables填写 `SITE_URL`，末尾不要带 `/`。3小时预览网址不能填写。随后手动再运行一次每日工作流；若同日已发布，先在本地运行 `SITE_URL=正式网址 npm run publication:prepare` 并提交RSS更新，或等待下一次正式发布。

在取得正式网址前，Production每日任务应保持未启用或因缺少 `SITE_URL` 明确停止；这能避免生成含本地地址或过期预览地址的RSS。

### 23. 验证自动部署

GitHub每日任务提交新简报后，EdgeOne应自动出现一次新部署。打开Makers项目的 Deployments，最新提交应成功并切换为Production。若失败，上一版本应仍可访问。

### 24. HTTPS和刷新

预览地址和后续正式域名均应使用HTTPS。预览测试时先打开带令牌的根地址，让浏览器保存3小时校验Cookie，再分别打开：首页、`/daily/`、`/archive/`、某个 `/archive/YYYY-MM-DD/` 和文章页。正式域名上线后再次直接刷新这些页面，所有页面应继续显示而不是404。

## E. 日常管理

### 25. 查看最新一期

打开EdgeOne网址。首页自动读取最近一次正式数据；今日页显示检索范围、候选数、入选数、全文/摘要分析数和是否从近30天扩展至半年。

### 26. 查看往期与RSS

- 往期：`正式网址/archive/`
- RSS：`正式网址/rss.xml`
- RSS说明：`正式网址/rss/`

RSS每期只有一个GUID，不会重复同一期。

### 27. 查看Token和费用

GitHub Actions单次运行Summary显示当日Token。仓库 `data/usage/YYYY-MM.json` 保存日/月汇总。Token标记为API返回值；费用按 `config/model-pricing.json` 估算，最终以AI服务商账单为准。公开网站默认不显示成本。

本地详细记录：启动项目后打开 `/admin/ai-usage`。公开Production页面只显示管理员查看说明。

### 28. 查看匿名访问统计

腾讯云控制台 → EdgeOne Makers项目 → **Metrics / Analytics / 指标分析**。查看请求量、路径排行、来源、设备、浏览器，以及平台实际提供的地区/运营商匿名汇总。不要开启付费自定义统计、实时日志或长期日志。

原文按钮通过 `/out/PMID/pubmed`、`doi`、`publisher`、`fulltext` 静态路径跳转，可在路径排行中查看匿名点击总量。

### 29. 修改每日篇数

GitHub Variables 修改 `DAILY_ARTICLE_COUNT`，范围1到5。最近30天不足时系统先扩展到180天，仍不足再扩展到360天；360天内仍不足高质量且未曾正式发布的文献时，允许少于此数。

### 30. 修改期刊和关键词

- 期刊：仓库 `config/journals.json`；
- 影响因子门槛和期刊数值：仓库 `config/journal-metrics.json`；
- 关键词：仓库 `config/topics.json`；
- 评分和比例：`config/scoring.json`。

在GitHub打开文件，点铅笔图标编辑，保存到main。`minimumImpactFactor` 默认是 `5`，`comparison` 默认是 `greater-than`，表示必须严格大于5；影响因子未知的期刊默认排除。每年新版JCR发布后，应同时更新对应期刊的 `impactFactor`、`metricYear`、`source` 和顶层 `verifiedAt`。不要删除JSON中的逗号或引号；不确定时先下载备份。

### 31. 更换AI模型或Key

- 更换模型：修改Variables中的 `AI_PROVIDER`、`AI_BASE_URL`、`AI_MODEL`；
- 更换Key：Secrets中点 `AI_API_KEY` → **Update secret**，粘贴新Key；
- 不要把Key填写到EdgeOne或任何网页源代码中。

更换后先手动运行一次，查看真实连接和质量检查结果。

### 32. 回退上一版本

EdgeOne：进入 Deployments，选择上一条成功部署，使用 **Rollback / Promote to Production / 重新部署**（名称以控制台实际显示为准）。

GitHub：进入仓库 Commits，找到出错提交，使用Revert生成反向提交；不懂时不要强制删除历史。回退后EdgeOne会自动重新部署。

### 33. 检查是否产生费用

每月至少一次：

1. 腾讯云 **费用中心 → 账单概览/资源账单**，确认EdgeOne为0元；
2. EdgeOne项目确认仍为Free，未订阅Add-on、未开自动续费；
3. GitHub **Billing and plans** 确认Actions与存储支出为0；
4. 确认没有LFS、Packages大型存储或收费Runner；
5. AI服务商账单应是唯一可能费用。

### 34. 关闭误开的收费服务

不要只删除代码。进入对应控制台：关闭自动续费 → 停止增值功能 → 销毁不需要的付费资源 → 确认账单不再增长。若看到已生成订单，先不要支付，联系腾讯云客服确认取消方式。

### 35. 真实网络验收

打开 `docs/中国网络测试表.md`，分别让移动、联通、电信、微信、iPhone、安卓、Windows和Mac用户勾选。只有真实测试过的项目才能写“通过”；自动化和单一Wi-Fi不能代表三大运营商。

## F. 发生故障时

- PubMed失败：任务重试后仍失败则不提交，旧站保留；
- Crossref失败：使用PubMed已有DOI信息继续；
- PMC失败：降级为摘要分析并标注；
- AI失败/余额不足/质量检查失败：不发布不完整简报；
- EdgeOne失败：使用上一版，按第32步回退；
- GitHub定时延迟：用第11步手动运行；
- 半年内不足5篇：正常少发并说明，不降低质量凑数；已正式发布的文献不会重复发送。

最后请记住：这个架构不需要购买服务器。除AI API外，GitHub标准免费额度与EdgeOne Makers免费版在小于100人的测试规模下应保持0元，但免费政策会变化，管理员仍需按第33步定期确认控制台实际状态。
