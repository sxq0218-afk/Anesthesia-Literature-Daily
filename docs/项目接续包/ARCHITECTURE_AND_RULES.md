# 架构与现行规则

## 系统架构

```text
GitHub Actions（每天北京时间约04:37）
  ↓
PubMed检索 + PMC开放全文 + Crossref补充
  ↓
正式历史去重
  ↓
影响因子 > 5硬筛选
  ↓
相关性与100分评分
  ↓
优先近30天，必要时依次扩展至180天和360天
  ↓
临床证据与基础研究分别按影响因子降序
  ↓
目标构成：4临床证据 + 1基础，不跨类别补位
  ↓
结构化提取 + 完整摘要翻译 + 精读V2
  ↓
统一事实与临床转化边界检查
  ↓
生成并校验静态JSON/网页/RSS
  ↓
先提交published历史和正式内容
  ↓
Buttondown邮件（同一期幂等）
  ↓
提交脱敏投递状态
```

公开网页只读取静态数据，不能读取密钥，也不能从浏览器调用AI。

## 文献数据来源

- PubMed：PMID、标题、作者、期刊、日期、摘要、MeSH、文献类型、DOI。
- PMC：判断并获取合法开放全文。
- Crossref：补充或核验DOI、日期、出版社入口。
- 禁止抓取或保存受版权保护的付费全文。

## 时间和数量

- `initialWindowDays=30`：优先最近30天。
- `expandedWindowDays=180`：条件不足时先扩展到最近半年。
- `maximumWindowDays=360`：180天仍不足时扩展到最近360天。
- `candidateLimit=2000`：分页检索的异常保护上限，不再只取最新120篇。
- `candidatePageSize=200`：PubMed候选分页大小。
- `journalAuditLimit=300`：每轮宽主题检索的未配置期刊审计样本。
- `dailyLimit=5`：每日最多正式推荐5篇。
- 每次扩展后在当前完整合格候选池中按影响因子选择，不以较短窗口覆盖更高影响因子文献。
- 360天内仍不足目标构成时允许少发，不跨类别补位，不用低质量文章凑数。

## PubMed检索条件

- 所有关键词在`Title/Abstract`字段检索。
- 必须存在摘要：`hasabstract[text]`。
- 正式候选检索直接限定到已核验、指标年份有效且JIF严格大于5的期刊，并分页读取至完成或达到异常保护上限。
- 宽主题检索只生成未配置、未知和过期影响因子的内部审计样本，不参与正式选文。
- 按PubMed发表日期倒序读取；最终在临床池和基础池内分别按影响因子、评分、证据质量和日期排序。
- 当前没有语言限制，也没有“仅RCT”限制。
- 仅在摘要或MeSH中顺带提到插管等宽泛词、但标题和正文缺乏直接麻醉/围术期语境的文章，相关性记为0并排除。

## 去重规则

配置与实现：`config/scoring.json`、`src/literature/dedupe.mjs`

- PMID相同：重复。
- DOI忽略大小写后相同：重复。
- 标题二元组相似度达到0.88：重复。
- `data/state/pushed.json`只保存正式发布历史。
- 只有`status=published`或旧版没有status的正式历史进入永久排除集。
- 候选、Demo、分析失败、未发布和仅验证记录不会永久排除。

## 期刊影响因子硬筛选

配置文件：`config/journal-metrics.json`

- 指标：Journal Impact Factor。
- 门槛：严格大于5。
- 等于5：排除。
- 未配置期刊：排除。
- 影响因子未知：排除。
- 指标年份超过允许新鲜度：排除。
- 数值和来源每年人工复核，不能让AI猜测。

- Journal of Clinical Anesthesia

## 评分规则

配置文件：`config/scoring.json`

总分100：

- 专业相关性30；
- 证据质量25；
- 临床影响20；
- 期刊质量15；
- 新颖性10。

最低正式候选分数为45，且专业相关性必须大于0。

证据类型优先大致为：指南/共识 → 系统评价/Meta分析 → RCT → 临床试验/多中心研究 → 观察性研究 → 病例报告。

## 研究构成与排序

- 目标为4篇临床证据和1篇麻醉相关基础研究。
- 临床证据包括临床原始研究、系统评价、Meta分析、指南和共识。
- 临床证据候选按影响因子降序取最多4篇，基础研究候选按影响因子降序取最多1篇。
- 影响因子相同时依次比较综合质量分、证据质量分、发表日期和PMID。
- 找不到目标构成时少发，不允许另一类别超额补位。
- 基础研究标题必须出现麻醉药、麻醉机制、镇痛或伤害感受相关信号。
- 综述、指南和其他非原始研究不是一律禁止，但只在构成或数量需要时补位。

## AI分析与质量控制

业务代码统一调用`generateAI()`，不直接绑定某一家模型。

第一轮提取固定结构化JSON，包括：

- 标题、期刊、日期、DOI、PMID；
- 研究类型、对象、样本量；
- 干预、对照、主要与次要终点；
- 结果、效应量、置信区间、P值；
- 不良事件和局限性。

独立翻译模块完整翻译PubMed摘要，保留结构、全部数字、组别方向和谨慎措辞。

精读V2按研究类型生成：

- 方法学拆解；
- 统计方法简介和本研究用途；
- 结果精析；
- 统计学意义与临床意义；
- 批判性评价；
- 临床适用性、不可外推范围、实践改变和证据缺口。

统一质量检查：

- 标题、PMID、DOI；
- 样本量、主要终点、效应方向；
- CI和P值；
- 观察性研究因果化；
- 统计学差异被误写为临床获益；
- 亚组过度解读；
- 摘要漏译、数字遗漏和方向翻反；
- 统计方法与原文不匹配；
- 基础研究直接提出临床干预建议；
- 原文不存在的信息。

失败时允许按配置重试；仍失败则不能正式发布。

PMC开放全文超过单次输入上限时：

- 完整摘要始终保留；
- 优先截取Methods、Results、Discussion、Limitations等重点章节；无法识别章节时才截取前后段；
- 分析依据明确标记为重点章节节选或前后段节选；
- 不突破单篇输入上限，不把节选称为全文分析。

## 发布状态

状态顺序：

```text
candidate → analyzed → validated → published
                         ↘ failed
```

只有完成检索、AI分析、结构校验、页面/邮件生成及正式发布后才能成为`published`。

自动邮件任务先保存并推送已验证的正式内容，再调用Buttondown。这样即使最终Git提交或网络发生故障，也不会出现“邮件已发但仓库没有对应简报”的不一致。Buttondown读取请求可重试；创建或发送类写请求不盲目重试，并会按期次主题查询既有草稿，降低重复投递风险。
